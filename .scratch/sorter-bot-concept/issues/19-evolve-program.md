# 19: Учебный заказ на изменение прежней программы

## Что сделать

Игрок развивает собственную программу при изменении требований, сохраняя обработку знакомых грузов.

## Зависит от

14 — Возвращаемое значение функции; 18 — Генерация грузов с покрытием случаев

## Критерии приёмки

- [x] Учебный заказ требует изменить прежнее решение, сохранив необходимое поведение.
- [x] Ранее написанный код остаётся основой для работы игрока.
- [x] Функции помогают организовать решение, но их использование не обязательно для зачёта.
- [x] Любое решение, выполняющее действующие требования, принимается.

## Проверка в Godot

1. Запустить `SorterGame.tscn` и выполнить первый заказ циклом из справки «Цикл while». Принять второй заказ. Убедиться, что программа осталась в редакторе, а в раскрытой карточке появилась подсказка об изменении маршрутов для обоих цветов.
2. Вернуть робота на старт кнопкой «Начать текущий груз заново» и запустить сохранённый цикл. Доставка по прежнему маршруту отклоняется. Счётчик второго заказа остаётся на «0 из 3».
3. Вернуть робота на старт и поменять условие прежнего цикла на `if color == "blue":`. Запустить исправленную программу. Верхняя зона принимает синие коробки, нижняя — оранжевые. Счётчик увеличивается только после доставки синих.
4. В тестовом сценарии `--evolve-program` проверить оба варианта программы для второго заказа. Первый выбирает маршрут условием в основном коде, второй выносит выбор маршрута в функцию. Каждый доставляет оба цвета.
