# Sorter Bot — инструкция для агента

## О проекте

«Sorter Bot» — образовательная игра на Godot 4.7 (GDScript, Forward Plus, Jolt Physics).
Цель игры — научить пользователя программировать.
В MVP игрок программирует робота, который раскладывает коробки по нужным зонам,
через встроенный интерпретатор Python-подобного языка.

## Правила взаимодействия

- Агент не принимает решений самостоятельно. Архитектура, логика, дизайн, новые
  функции — только по решению пользователя.
- Перед любым нетривиальным действием (изменение структуры проекта, добавление
  файлов, изменение логики) — спросить и дождаться ответа пользователя.
- Если агент считает, что нужно что-то добавить, улучшить или изменить — сначала
  объяснить зачем и спросить разрешения. Без разрешения не делать.
- Не переписывать, не удалять и не «улучшать» существующий код без явного
  разрешения пользователя.
- По непонятным и спорным моментам — спрашивать, а не догадываться.
- Если после двух попыток решение не найдено или возникла неясность — остановиться,
  описать проблему и предложить 2–3 варианта решения на выбор пользователя,
  вместо бесконечных самостоятельных попыток.
- Общение, вопросы и объяснения — на русском языке.

## Формат предложений изменений

- Изменения в существующем коде предлагать в виде unified diff или четко
  обозначенных блоков (`# ... существующий код ...`), чтобы минимизировать ошибки
  при ручном копировании.
- Новый файл с нуля — предоставлять его полное содержимое.
- При предложении новой логики или исправлении бага кратко описать, как проверить
  изменение в редакторе Godot (например: «Запустите сцену `level_1.tscn` и
  нажмите кнопку X»).

## Стиль кода

Следовать [GDScript Style Guide](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/gdscript_styleguide.html)
из официальной документации Godot. Ключевые правила:

- Отступы — табуляция (по ширине = 4 пробела).
- `snake_case` для файлов, функций и переменных; `PascalCase` для классов,
  узлов и сцен.
- Сигналы — прошедшим временем (например, `box_dropped`).
- Один класс на файл; `class_name` — в `PascalCase`.
- Порядок членов класса: `@tool`, `extends`, `class_name`, сигналы, перечисления,
  константы, переменные, `@onready`/`@export`, `_init()`, `_ready()`,
  публичные методы, приватные методы (с `_`), статические методы.
- Комментарии и документация в коде — на русском языке.

## Организация проекта

Структура папок и именование файлов — по руководству
[Project organization](https://docs.godotengine.org/en/stable/tutorials/best_practices/project_organization.html):

- `scenes/` — сцены (`.tscn`)
- `scripts/` — скрипты (`.gd`)
- `assets/` — ресурсы: текстуры, звуки и т.п.
- Сцена называется так же, как её корневой узел.

## Что нельзя трогать без спроса

- `project.godot`
- Структуру папок проекта
- Папка `.godot/` — автогенерируемая, в контроль версий не входит

## Контекст проекта

- Встроенный интерпретатор Python-подобного языка — отдельная подсистема игры.
  Его синтаксис и семантика определяются проектом, не путать с GDScript.
- Не предполагать наличие функций Python (например, `print`, `len`) во внутриигровом
  языке, пока их существование не проверено по коду интерпретатора или документации
  проекта.
