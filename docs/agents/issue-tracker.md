# Трекер задач: локальный Markdown

Задачи и спецификации проекта хранятся в `.scratch/`.
Внешний сервис не используется.

## Структура

- Одна функциональность — одна папка `.scratch/<feature-slug>/`.
- Спецификация — `.scratch/<feature-slug>/spec.md`.
- Каждая задача — отдельный файл:
  `.scratch/<feature-slug>/issues/<NN>-<slug>.md`.
- Нумерация задач внутри папки начинается с `01`.
- Не объединять несколько задач в один файл.
- Имена папок и файлов — короткие, в kebab-case.
- Содержимое документов — на русском языке.

## Состояние задачи

В начале файла указывать строку `Status:`.
Значения: `open` — открыта, `in-progress` — выполняется,
`closed` — завершена.

Комментарии и историю обсуждения дописывать в конец файла
под заголовком `## Comments`.

## Публикация

Если навык просит опубликовать спецификацию или задачу в трекере,
создать соответствующий Markdown-файл по указанным выше правилам.
Папки создавать по мере появления документов.

## Чтение задачи

Читать файл по указанному пользователем пути.
Номер задачи уникален только внутри папки функциональности.
Если по номеру найдено несколько задач, уточнить нужную.

## Согласование работы

Создание задачи и её статус не заменяют разрешение пользователя
на изменение проекта. Соблюдать правила из `AGENTS.md`.
